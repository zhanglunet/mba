## 1. 一句话现状

**MBA = Metric Brand Auditor**：把品牌影响力拆成可打分、可比较、可复盘的自动化流水线。形态是 Claude Code skill（`/mba <brand>`）+ npm 上的 MCP server（`mba-mcp-server`）+ 静态站 https://mbabrand.com 。

| 项 | 内容 |
|---|---|
| 版本 | v0.6.1（2026-07 发版；main 仍跑 Brand Watch 日更） |
| 技术栈 | pnpm monorepo · Node≥20 · Python 校验 · 自包含 HTML 报告 |
| 规模（文档自报） | 24 品牌报告 · 43 人物评委 · 10 套 panel · 7 维 × 5 镜头 |

## 2. 定位

出处：`README.md`「定位与愿景」、仓库 description、`CLAUDE.md`、`docs/26-system-overview.md`。

> **给「一人公司」做的品牌影响力审计师。** 以前品牌调研、舆情监测、竞品跟踪、定期品牌健康报告是大公司市场部 + 咨询才玩得起的；mba 做成一个人也能跑的自动化工具——`/mba <brand>` 一行，得到可打分、可比较、可复盘的版本化审计报告。

怎么做：多智能体并行调研 + panel 人物评委独立打分（互不可见）+「元评审」盯评委一致性。

目标用户（`docs/01-prd.md` §3）：主用户 = AI Native 早期投资人/FA、品牌运营/创始人/GTM；次用户 = 内容创作者、想复用「品牌评估」组件的 agent 开发者。明确**不是**非技术 GUI 用户、「5 分钟出报告」用户、只要好评的人。

## 3. 目标

**产品愿景句**（`docs/01-prd.md` §1，文档标题即「项目愿景」）：

> 让「评估一个品牌的影响力」从一项**手工咨询服务**变成一条**可重复执行、可演化追踪、可跨品牌可比**的自动化流水线。

对应三大顽疾的解法：多评委并行、版本化 + EVOLUTION、固定 5 镜头 × 7 维度坐标系。

**成功指标**（同文档 §6）：

| 阶段 | 成功线 |
|---|---|
| 短期 v0.x | 跑通 5+ 真实品牌；评委能稳定区分；HTML 渲染零错 |
| 中期 v1.0 | ≥3 外部用户独立用过；至少一份进真实决策；评委扩展点被用过 |
| 长期 | MCP 化后嵌入 ≥2 个 agent 框架 |

**非功能**：FRESH ≤30 min / EVOLUTION ≤10 min；单次 FRESH ≤$5；结论可追溯到 `_raw/`。

**当前产品形态**（README / docs/26）：已从「出报告」扩到「审计循环 + 舆情循环」——舆情只建议重审、**永不自动改分**；分数只在评委 in-character 重打时变。

## 4. 愿景

出处：`README.md`：

> **愿景**：让个人和小团队拥有「品牌雷达」。每天早上打开指挥舱——健康分多少、网上在聊什么、竞品干了什么，一目了然；分数掉了，飞书第一时间告诉你。最终，把品牌影响力变成像看财报一样日常的东西：**可量化、可比较、可复盘**。

`docs/01-prd.md` §1 的「项目愿景」更偏**产品机制愿景**（手工咨询 → 可重复流水线）；README 更偏**用户体验愿景**（品牌雷达 / 指挥舱 / 像财报一样日常）。两者互补，不矛盾。

**推断（非原文）**：从已落地的 watch 驾驶舱、飞书分层预警、PRD-062「一人公司指挥舱」表述看，近期产品叙事正从「单次审计报告」往「每日可打开的品牌操作系统」靠——这是对 README 愿景句的延伸读法，不是新口号。
