## 做了什么

T3 在 T2 之上加闸门层（新模块 `scripts/skill_discovery_gate.py`，T2 代码未动）：

- `verify_trace`：推荐可溯源——每条候选须有非空 matched 与 reason；recommendation.trace 须等于首位候选的 reason、recommendation.skill 须等于首位候选；分数须在 [0, 1]；无候选时 recommendation 须为 None。
- `review_recommendation`：推荐可复核——人对一条 pending 推荐接受（accepted）或否决（rejected），只可复核一次；接受/否决均须留 reviewer；否决须写 note（推错可纠：否决原因回流，供后续调关键词权重）；否决后 recommendation 保留 trace 备查，但置 effective=False（该推荐不再生效），接受则 effective=True。
- `GatedDiscoveryLedger`：入账闸门，继承 T2 DiscoveryLedger；入账时先验 trace（DISCOVERY_TRACE_MISMATCH），再验复核记录一致性（已复核的须有 reviewer、否决的须有 note 且 effective=False）；否决记录入账即记一条纠正（按需求原文归一化键）。
- `recommend_corrected`：纠正重推——同一需求重推时排除已被否决的 skill，次位候选顶上；新记录 request.supersedes 指向上一次 request_id；全部候选都被否决则返回空推荐（不硬推）。

## 与 T2 的关系

- T2 的 `review.verdict` 恒为 pending（待人工复核）；T3 落地接受/否决回路。T2 的 `recommend()` 行为不变；无纠正时 `recommend_corrected()` 与 T2 输出一致（测试断言相等）。
- 落地差异（T2 已确认，T3 沿用）：mba manifest 无 keywords 字段（缺失容忍）；registry 只覆盖 43 个视角，3 个消费者视角由 perspectives/ 目录补齐；中文分词用 2–4 字 n-gram。
