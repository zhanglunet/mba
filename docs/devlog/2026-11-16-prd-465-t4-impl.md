## 做了什么

T4 在 T2/T3 之上加划界断言层（新模块 `scripts/skill_discovery_boundary.py`，T2/T3 代码未动）。发现层只做"发现"，不管以下两件事：

- `scope_check`：递归扫描发现记录，越界字段一律显形为 violation——评审域（R1：`findings` / `review_score` / `audit_score` / `judge_score` / `judge_verdict` / `verdict_score` / `rating` / `scorecard` / `brand_audit_report` / `review_report`）、安装域（R2：`install` / `installed` / `install_path` / `install_command` / `install_action` / `install_status` / `installed_version` / `registry_write` / `marketplace_write`）；顶层多余键、各段多余键也在断言范围内。精确键名匹配，不误伤发现层自有字段（候选 `score` 是发现置信分，`review.verdict` 是发现复核结论，测试钉住）。
- `assert_no_review_writes` / `assert_no_install`：两条红线各一条断言入口，分别对应 R1 / R2。
- `BoundaryDiscoveryLedger`：入账划界，继承 T3 `GatedDiscoveryLedger`；越界记录拒绝入账（`DISCOVERY_OUT_OF_SCOPE`），洗不进账本。
- `recommendation_shape_check`：推荐输出形态断言——顶层键恰为 schema/request/candidates/recommendation/review 五段，候选只含 skill/score/matched/reason，推荐只含 skill/trace/effective，不带安装动作、不带评审写字段。
- `snapshot_sources` / `sources_unchanged`：索引源只读断言——发现全流程前后，registry.json / SKILL.md / manifest.json / marketplace.json 的字节内容须一字不差（发现层只读，不改源数据；R2：不写 registry / marketplace）。

- T2 已断言推荐记录无 findings；T4 把"不碰评审分数、不碰安装链路"扩展成系统划界：两域字段表 + 入账划界 + 输出形态断言 + 索引源只读断言。
- T3 的纠正重推（否决首位、次位顶上）全程在界内（测试断言：重推记录过 scope_check，supersedes 链路不引入越界字段）。
