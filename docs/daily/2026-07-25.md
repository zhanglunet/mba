### 踩坑(六个,都值得记)

1. **PR 没有 CI check ≠ Actions 坏了** —— `pull_request` workflow 跑在 merge ref 上,
   **PR 有冲突时算不出 merge commit → 校验 workflow 静默不触发**,而 Cloudflare(基于 head commit)照跑,
   看起来像"只有一项 CI"。当时误判为 Actions 配置/配额问题,白等 15 分钟。
   实证:`8352ed0`(有冲突)→ 0 run;rebase 成 `3472e79` → 2 run 立即全绿。已固化进 `CLAUDE.md`。
   ⚠ 诱因:**每日舆情 PR 自动合并会重生成 `site/index.html`**,隔夜分支极易冲突 —— 开 PR 前先 rebase。
2. **手写的"会过期数字"没人守** —— `agents.html` 停在 `v0.1.0` 而 npm 已发 `0.2.0`,
   **整整一个版本周期没发现**;"220 tests" 实测也只有 215。→ 催生 #197 的门禁。
3. **门禁自身也会有洞** —— #197 第一版用「两文件命中**总和** > 0」判断,
   red-green 第三个场景(删掉 `agents.html` 版本号)**仍然绿**——被 `docs/README.md` 那处兜住,
   等于 gate 对该文件静默失效。已改为**逐文件要求**。
   教训:验门禁不能只验"能报红",还要验"**不会被绕过**";只跑场景 ①② 就会推一个看着能用、实则有洞的 gate。
4. **复用别人的 `call_llm` 会静默继承别人的 prompt**(#201)—— `prescreen` 复用
   `classify_candidates.call_llm`,但那函数用**模块级 `SYSTEM`**;不显式传自己的,模型在**答另一道题**,
   还不报错,只在解析时炸成裸 `JSONDecodeError`。同批还撞上 `max_tokens=2000`(17 家输出被截断)。
   → 形参开放 `system/max_tokens/timeout`;截断报错改成**点名 max_tokens**,不再是裸 JSON 错。
5. **`--dry-run` 只估了输入,没估输出**(#201)—— 所以「预演绿、真跑红」。dry-run 现在**逐批**打印
   入/出两个估算 + 上限 + timeout。教训:预演要覆盖**真跑会撞的每一个上限**,不然它只是个安慰剂。
6. **分批口径错:按品牌数切,payload 却取决于事件数**(#202)—— 6 家 × 平均 30 条 = 195 条 ≈ 11.5k token,
   90s 全批超时。改按**事件数**切(≤70)+ 每品牌限 18 条(**P0>P1>P2 优先,保证限量不把 P0 挤掉**)
   → 11.5k 降到 ~3.3k/批。教训:**分批要按真实的成本维度切**,不能按"看起来是单位"的那个维度。
