## 3. 引用语法

### 3.1 形态（T2 实现口径）

| 形态 | 示例（占位） | 解析目标 |
|---|---|---|
| 评委包引用 | `@评委包名` | 包 + 成员清单指纹（包名全库唯一，PRD-233 登记册不变量） |
| 作品引用 | `@作品号` | 作品 id（十进制编号） |

### 3.2 禁止形态（出现即 `REF_SYNTAX_ERROR`，不尝试理解）

- `@评委包名#成员`——引用不带成员后缀（成员清单是指纹整体，不逐人寻址）；
- `@作品号/评论`——作品引用不带子对象（评论寻址不定义）；
- `@最新评委包`——相对词不是引用（与 292 同口径：最新版是业务裁决）。

## 4. @名→id 解析 schema

### 4.1 产物 schema（T2 预埋）

```json
{
  "schema": "ref-resolution/v1",
  "raw": "@评委包名",
  "kind": "judgepack|work",
  "judgepack": {"name": "…（占位）", "member_count": 12, "fingerprint": "sha16:…"},
  "work_id": null,
  "resolution": {"status": "resolved", "candidates": 1, "strategy": "exact"}
}
```

- 指纹 = 包成员清单规范化 JSON 哈希（PRD-233 登记册口径）——指纹进结论即天然审计（评审用了哪一版包，可复核）；
- 作品解析附存在性元信息（在库/已撤回），撤回作品引用照常寻址、显形标注（不做业务拦截）。

### 4.2 解析步骤（确定性）

1. 取候选集：评委总登记册（PRD-233 registry.json）+ 作品登记（既有作品库，只读）；
2. 精确匹配：包名全等；作品号整数全等；
3. 候选数裁决：=1 resolved；=0 `REF_NOT_FOUND`；>1 `REF_AMBIGUOUS`（登记册不变量下包名冲突不应出现——出现即 `REF_REGISTRY_CORRUPT` 显形）。

## 5. 歧义闸门（T3 预埋）

| 错误码 | 触发 | 行为 |
|---|---|---|
| `REF_SYNTAX_ERROR` | §3.2 禁止形态 | 报错回显位置，评审不开始 |
| `REF_NOT_FOUND` | 候选 0 | 报错 + 可用包/作品清单摘要，不开始 |
| `REF_AMBIGUOUS` | 候选 >1 | 停下问，不开始 |
| `REF_REGISTRY_CORRUPT` | 登记册不变量破坏 | 报错显形（数据问题，不掩盖） |

- 词表封闭；解析返回 `Resolution | Refusal` 二型。

## 6. 结论引用字段与审计

- 评审结论新增 `ref_resolutions` 数组：逐引用 `{raw, kind, judgepack_fingerprint?, work_id?, status}`；
- 口径变更仍走 PRD-282 快照：引用解析记录的是**用了哪一版**，不是**改口径**——两字段并存不混用；
- 审计：每次解析追加 `{ts, raw, kind, status, candidates, error_code?}`，只增不删。
