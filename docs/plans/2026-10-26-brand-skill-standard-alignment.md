## 1. 定位与口径声明

1.1 PRD-234 的目标是把 mba 的品牌技能（skill 文件）按 Agent Skills 开放标准对齐，做到跨工具（Claude / Cursor / Codex / Pi）可发现、可加载。T1 只做盘点，交付"两清单"：品牌技能清单（§4）与标准差距清单（§6）。

1.2 唯一口径源：本文档及 T1 全部产出中的"标准要求"，只以 PRD-199 为准。本仓只做适配，不复制、不转译、不另立任何口径。本文档任何规则若与 PRD-199 冲突，一律以 PRD-199 为准，并须在评审中修订本文档。

1.3 形态借鉴声明：本文档在"技能文件组织形态"层面（frontmatter 承载元信息、正文分节承载三要素）借鉴开源仓库 google-labs-code/stitch-skills 的形态。**该仓库协议未核实，仅借鉴形态，不复用其任何代码、键名或文案**；凡涉及具体键名、字段、格式之处，一律以 PRD-199 当前版本为准。

### 2.2 版本标注

- 本文档头部"依据口径"字段记录盘点所依据的 PRD-199 版本；差距清单每行的等级判定默认继承该版本。
- 盘点过程中 199 若升版：尚未评审的部分整体重判；已评审部分按 §2.3 处理。

### 2.3 口径变更跟随流程

1. 199 发布新版本后 3 个工作日内（占位时限，评审可调），盘点负责人 diff 新旧版口径，标出受影响锚点；
2. 仅重判受影响锚点对应的差距清单行，"标准要求"与"T2 改法要点"同步更新；
3. 更新本文档头部"依据口径"版本号，并在文档变更记录登记"口径同步"；
4. 受影响行超过全部行数 30% 时，差距清单整体重新评审。

## 3. 盘点范围

### 3.1 纳入

| 范围 | 说明 |
|---|---|
| 技能根目录 | `<skills 根目录占位>`（盘点启动时确认实际路径并登记到盘点记录）下全部技能目录 |
| 技能主文件 | 每个技能目录的 SKILL.md 或同构文件（含技能类 frontmatter 的主文件） |

- 技能正文的业务内容质量（文案好坏、策略对错、词表取舍）：T1 只看结构与元信息对齐，业务内容在 PRD-234 全程不改。
- 非品牌域技能：扫描命中即登记移交 PRD-234 范围外负责人 `<移交负责人占位>`，不评级、不进差距清单。
- 工具侧配置（各工具挂载技能的配置文件）：仅作为 §4.2 步骤 5 的验证环境，不作为盘点对象。

## 4. 盘点方法

### 4.1 盘点字段（品牌技能清单，一技能一行）

| 字段 | 说明 | 采集方式 |
|---|---|---|
| 技能 ID | 目录名或现行 slug，原样登记 | 文件系统 |
| 技能名 | frontmatter name；缺省取文件一级标题；均无记「无」 | 文件读取 |
| 文件路径 | 相对仓库根的路径；后续现状摘录一律附 `path:line` | 文件系统 |
| 类别 | §7 分类之一，允许暂记「待归类」 | 人工判定 |
| TRG 现状 | 触发描述有无及内容摘要（≤1 句） | 摘录 |
| SCOPE 现状 | 适用/不适用边界有无及摘要 | 摘录 |
| IO 现状 | 输入参数、输出产物定义有无及摘要 | 摘录 |
| NAME 现状 | 目录名、目录层级、资产引用路径形态 | 文件系统 |
| ALIAS 现状 | 现存旧触发词/别名清单（含历史文档中的旧叫法） | 摘录 + 全文检索 |
| VER 现状 | 是否写明对齐所依据的标准版本及具体写法 | 摘录 |
| 加载现状 | 四工具可发现/可加载冒烟结果 | §4.2 步骤 5 |
| 备注 | 移交记录、待核原因等 | 自由文本 |

### 4.2 盘点流程

| 步骤 | 内容 | 产出 |
|---|---|---|
| 0. 基线冻结 | 在 `<分支名占位>` 上锁定并记录 commit `<commit-hash 占位>`；盘点期间基线变更须重跑步骤 1–2 并登记 | 基线记录 |
| 1. 机械枚举 | 运行枚举命令模板（见下），得到候选文件全集 | 候选文件列表 |
| 2. 归并去重 | 同名、别名、软链、多目录同技能归并为一个主条目；被归并的旧叫法记入 ALIAS 现状 | 主条目列表 |
| 3. 字段抽取 | 逐文件按 §4.1 摘录，只摘录不评价，每条现状附 `path:line` | 技能清单（草稿） |
| 4. 比对评级 | 按 §5 判据逐锚点评级，填写差距清单 | 差距清单（草稿） |
| 5. 阻塞验证 | 对疑似阻塞项做四工具加载冒烟（环境 `<沙箱环境占位>`，账号 `<测试账号占位>`），记录阻塞面 | 阻塞面记录 |
| 6. 抽样复核 | 抽取 ≥20%（占位比例，评审可调）条目由第二人 `<复核人占位>` 复核；发现不一致即全量回炉该批次 | 复核记录 |
| 7. 汇总评审 | 产出两清单 + 本文档提交评审，评审通过后归档并关闭 issue #1170 | 交付物 |

枚举命令模板（路径为占位，启动时按实际目录替换；命令与输出原样存入盘点记录）：

```bash
# 主枚举：技能主文件（按实际文件名调整匹配式）
git ls-files | grep -Ei '(^|/)skill\.md$'
# 兜底：扫描散落的含 frontmatter 的 Markdown
rg -l --glob '*.md' '^---\s*$' -- <skills-根目录-占位>
```

### 4.3 枚举完整性判据

技能清单条数 = 步骤 1 枚举文件数 − 归并数，且每条归并可解释；清单中不允许出现来源不明条目；「待归类」条目必须进入评审议题，不得私判后隐匿。

## 5. 差距判定规则

### 5.1 差距等级判据

| 等级 | 判据（满足其一即成立） |
|---|---|
| 缺失 | 对应锚点内容在文件中不存在；或存在但为空、为占位词（如 TODO/TBD） |
| 不完整 | 内容存在但缺必备子项：TRG 无触发词或无触发场景；SCOPE 只有适用无不适用（或相反）；IO 缺输入或缺输出；ALIAS 有别名但清单不全 |
| 不规范 | 内容齐全但形式不合规：目录名/slug/层级违反 NAME；版本号格式或位置违反 VER；别名承载方式违反 ALIAS |
| 已对齐 | 内容与形式均符合 PRD-199 当前版本 |
| 待核 | 无法判定（如需 199 条目澄清、需工具实测）；必须附原因与消解截止日期，禁止留空 |

判定从属规则：一个检查字段只记一个等级，取最高严重级（缺失 > 不完整 > 不规范 > 已对齐）；「待核」为临时态，定稿评审前必须全部消解。

### 5.2 阻塞面判定

定义：某差距若导致任一目标工具（Claude / Cursor / Codex / Pi）出现解析失败、不可发现、或发现后不可加载，记为阻塞，并在"阻塞面"列登记受影响工具列表。

典型阻塞形态（示意，最终判据以 PRD-199 及四工具实测为准）：frontmatter 整体解析失败；NAME 违规导致目录在工具中不可发现；TRG 缺失导致工具无法决策是否加载。判定一律以 §4.2 步骤 5 的实测记录为证据，不得凭经验推断阻塞。

### 5.3 证据要求

每个等级判定必须附证据：现状摘录（≤1 句）+ `path:line`；「已对齐」同样要给出证据，不允许凭印象判定。

## 7. 分类盘点框架

| 类别 | 典型形态 | 盘点时重点看什么（预计差距方向，非已盘点结论） |
|---|---|---|
| 品牌策略类 | 多步骤长文档（品牌定位、策略推导等） | SCOPE：是否写了"不适用"边界——策略类最易被过度触发；IO：输入资料清单与输出结构是否定义；ALIAS：历史叫法是否留存 |
| 文案生成类 | 模板 + 词表驱动（口号、slogan、社媒文案等） | TRG：触发词是否具体到品类，避免与通用写作技能抢触发；ALIAS：旧触发词是否保留，直接影响既有用户习惯；IO：输出产物格式是否定义 |
| 视觉规范类 | 规范文档 + 资产引用（色彩、字体、logo 使用等） | NAME：资产相对路径与目录层级是否合规；IO：输入参数（尺寸、媒介等）是否定义；阻塞面：资产路径断裂是否导致加载失败 |
| 评审类 | 检查单式（文案评审、设计稿评审等） | TRG：何时触发评审、何时不触发；SCOPE：非品牌物料是否被明确排除；IO：评审报告的输出结构是否定义 |
| 待归类 | 兜底 | NAME：是否应拆分或归并；无法归类必须挂"待归类"进评审议题，不得私判 |

各类使用同一张差距清单表、同一套字段，不按类别另设表格；类别仅用于决定盘点时的重点检查顺序与 §4.2 步骤 6 的分层抽样。

## 8. 对齐优先级规则

### 8.1 优先级矩阵

| 差距等级 \ 阻塞 | 阻塞任一工具 | 不阻塞 |
|---|---|---|
| 缺失 | **P0** | P1 |
| 不完整 | **P0** | P2 |
| 不规范 | P1 | P2 |
| 已对齐 | 复核阻塞原因后再定级 | P3（仅复核） |
| 待核 | **P0**（先消解判定） | P1（先消解判定） |

规则说明：

- P0 = 阻塞跨工具加载的差距，无条件最优先：这是 PRD-234"跨工具可发现、可加载"的硬门槛，一项阻塞即整技能不可达。
- 「待核」若可能阻塞，按 P0 处理：先消解判定，再进 T2 改法队列。
- P1 = 不阻塞但要素缺失（含 ALIAS 缺失），或阻塞存疑的不规范项。
- P2 = 不阻塞的不完整/不规范项，T2 第二批。
- P3 = 已对齐项，不进改法队列，仅参与 T2 完成后的回归复核。

### 8.2 同级排序键

优先级相同者依次按以下键排序：

1. 受影响工具数多者优先（阻塞面广的先改）；
2. 涉及旧触发词别名（ALIAS）者优先——直接影响既有用户触发习惯；
3. 类别默认序：文案生成 > 评审类 > 品牌策略类 > 视觉规范类（高频直用技能先改；评审会可调整）；
4. 技能名升序（保证全序、可复现）。

### 8.3 T2 批次划分

- 批次 1 = 全部 P0；批次 2 = 全部 P1；批次 3 = 全部 P2。
- 批次 1 完成后必须复测四工具加载冒烟，全部通过才进批次 2。
- T2 期间新增或变更的技能：先按本清单框架做增量盘点，再按等级插入对应批次，不允许跳过盘点直接修改。

## 9. 非目标

1. 不改品牌技能的业务内容：文案、策略、词表、规范正文在 T1/T2 一律不动，只做结构与元信息对齐。
2. 不另立标准口径：不定义新键名、新格式、新等级体系；一切判定以 PRD-199 为唯一口径源。
3. 不做跨仓治理：非品牌域技能只登记移交，不评级、不修改。
4. 不做工具侧开发：四工具仅用于加载验证，不改任何工具及其配置。

## 10. 验收点清单（对应 trend issue #1170）

T1 完成标准 = "清单框架与盘点方法可直接被 T2 执行"，逐项验收：

| # | 验收点 | 通过判据 |
|---|---|---|
| 1 | 技能清单完整 | 枚举命令与输出可复现且已归档；基线 commit 已登记；归并均可解释；无来源不明条目；无未消解的"待归类"（或已形成评审决议） |
