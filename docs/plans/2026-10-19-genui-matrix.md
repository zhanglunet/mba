# PRD-081/T1：生成式 UI 意图→图表决策矩阵设计

> 依据：trend `adopted/PRD-081-mba-generative-ui.md`（2026-10-19）；
> PRD-062/T1 信息架构 `docs/plans/2026-10-18-command-deck-ia.md`（§三指标清单、§五 deck.json 口径）；
> 看板实现 `dashboard.html`（风格资产：`--paper #faf8f3` / `--accent #c1440e` / serif 字体栈 / chart.js@4.4.4 CDN）。
> T1 只定决策矩阵（意图目录 + fallback 规则 + 集成形态），不写实现代码。
> 借鉴 CopilotKit/OpenIntelligentUI（MIT 已核实）的"意图→图表决策矩阵"+"受控组件"思路，只借鉴思路，不复用代码。

## 一、设计原则

1. **只读**：问答全程只读 `data/deck.json`，不写文件、不调外部接口、不触发重审、不改告警（PRD 红线）。
2. **受控组件**：输出限定在预注册的几种图表/卡片/列表里，规则只能"选"不能"现编"——不做开放式 HTML 生成。
3. **诚实边界**：答不上来就说答不上来，不编图表、不猜答案；null 数据显示"数据暂缺"。
4. **确定性**：同一问题每次返回同一意图、同一图表（纯规则，无 LLM，零成本可复现）。
5. **风格一致**：复用指挥舱同一套 CSS 变量、字体栈、chart.js@4.4.4，看起来像一家人。

## 二、意图目录（第一期 8 个，不增不减）

PRD §方案/T1 给了 8 意图初版表。T1 逐项核对后**结论：8 个全保留，不增不删**。

理由：8 个意图与信息架构 §三的"一期指标清单"恰好一一对应——

| 区块 | IA §三一期指标 | 对应意图 |
|---|---|---|
| 品牌健康度 | 综合评分 / 5 lens 雷达 / 版本与日期 / 变化指示（Δ） | 查总分 / 维度雷达 / 查总分（含版本·日期） / 版本变化 |
| 舆情 | 近 7 天声量曲线 / 正负面占比 / Top3 热点事件 / 采集状态 | 声量趋势 / 口碑 / 热点事件 / null 降级（数据暂缺卡，非意图） |
| 竞品动态 | 竞品关键事件 Top5 / 对标品牌清单 / （预留）对标评分对比 | 竞品动态（含 watch_list 副标题展示） / —（二期，comparison 仍为 null） |

多一个意图都是范围蔓延（PRD 红线：只读、单品牌 demo）；少一个则有指标问不出来。8 个是"最小完备集"。

### 2.2 唯一归属判定规则（给 T2 路由器用）

8 个意图两两之间的数据源或问法都有明确分界。T2 的关键词路由器按以下三层裁决，**保证每个问题只落到一个意图**：

**第 1 层——排他词优先**（解决设计好的重叠对）：

| 重叠对 | 排他词 → 归属 |
|---|---|
| `rivals` vs `events`（都是事件列表） | 含"竞品/对手/对标/友商" → `rivals`；否则 → `events` |
| `sentiment` vs `volume`（都读 daily_volume） | 含"正负面/正面/负面/口碑/好评/差评/占比/比例" → `sentiment`；含"趋势/走势/曲线/每天/每日/近7天/7天" → `volume` |
| `compare` vs `radar`（都读 lenses[]） | 含"最强/最弱/最高/最低/排名/排序/对比/哪个…高" → `compare`；含"雷达/画像/全貌/整体/分布" → `radar` |
| `delta` vs `total`（都问分数） | 含"上版/上次/上一版/变化/涨跌/涨了/跌了/对比上" → `delta`；否则 → `total` |

**第 2 层——命中计数**：排他词未命中时，命中触发关键词多的意图胜出（各意图触发词见 §2.3）。

**第 3 层——固定优先级**（前两层仍平局时的最终裁决，窄口径优先）：
`rivals` > `events` > `delta` > `sentiment` > `volume` > `compare` > `radar` > `total`

口径：主体限定（竞品）> 时间限定（版本变化）> 切面限定（正负面）> 全量快照（总分/雷达）。平局本就罕见（排他词已覆盖 90% 以上的真实问法），第 3 层只是保证确定性。

**第 0 层——写操作拦截**（在意图匹配之前）：问题含"重审/重新打分/推送/发送/刷新/修改/删除/告警"等写操作动词 → 直接走 fallback（§三），不进入意图匹配。只读红线在路由层就掐死。

### 2.3 各意图触发关键词（T2 映射表输入）

> T2 `ask_router.py` 直接照这张表实现"关键词/短语 → 意图"映射。短语命中权重高于单词（实现细节 T2 定）。

- `total`：总分、综合评分、多少分、评分、归一化、健康度、哪一版、版本
- `compare`：最强、最弱、最高、最低、排名、排序、对比、哪个维度、谁高谁低
- `radar`：雷达、画像、全貌、整体、分布、五个维度、维度情况
- `delta`：上版、上次、上一版、变化、涨跌、涨了、跌了、Δ、delta、对比上、动了
- `volume`：声量、音量、讨论量、热度、趋势、走势、曲线、每天、每日、近7天、7天
- `sentiment`：正负面、正面、负面、口碑、好评、差评、占比、比例、中性
- `events`：热点、大事、事件、新闻、发生了什么、新消息、动态（无"竞品"时）
- `rivals`：竞品、对手、对标、友商、同行

### 2.4 null 降级（与 IA §三/§四口径一致）

- `health` 段：一期恒为非 null（随报告产出事件驱动更新）；若未来为 null，`total/compare/radar/delta` 统一返回"数据暂缺"卡。
- `sentiment` 为 null → `volume` / `sentiment` / `events` 不画空图，返回灰色"数据暂缺"卡片（复用 dashboard 的 `--missing-bg #f0ede7` 样式口径）。
- `competitors` 为 null → `rivals` 返回"数据暂缺"卡。
- `competitors.comparison` 一期恒为 null：**不设意图**，问"和竞品比分数"走 fallback（二期多品牌视图再说，IA §三已预留）。

## 三、fallback 规则

### 3.1 触发条件（满足任一即 fallback）

1. 三层裁决后无任何意图命中（关键词一个没中）；
2. 第 0 层拦截到写操作动词（重审/推送/刷新/修改/删除等）；
3. 问的是 deck.json 里没有的数据（如股价、营收、预测类"明年会涨吗"）——同样命中不了意图，自然落到这里。

### 3.2 固定返回文案（逐字稿，T4 直接用）

> 这个问题我答不上来。这个 demo 是只读的，只能聊指挥舱里已有的数据：品牌健康度（综合评分、5 个维度、版本变化）、舆情（近 7 天声量、正负面占比、热点事件）、竞品动态。
>
> 你可以问我，比如：「综合评分多少？」「哪个维度最弱？」「和上版比变了多少？」「最近 7 天声量怎么样？」「正负面占比如何？」「最近有什么大事？」「竞品在干什么？」

### 3.3 铁律

- 纯文本返回，**不画任何图表**（fallback 不是第 9 种意图，没有输出形态）。
- 不猜答案、不编数据：超纲问题（如"deepseek 股价多少？""明年品牌影响力会涨吗？"）一律走上面这段文案，不给"看起来像答案"的东西。
- 文案里的 7 个示例问题 = 8 个意图各取 1 个（`total/compare/delta/volume/sentiment/events/rivals` 全覆盖，`radar` 的问法并入"5 个维度"一句），用户一点就通。
- T5 验收：5 个超纲问题全部走 fallback，无编造（PRD §T5 已列验收项）。

## 四、集成形态：独立 demo 页 `ask.html`（定案）

**结论：做独立的 `ask.html`，不嵌入 `dashboard.html`。**

理由：

1. **零风险碰已上线看板**：`dashboard.html` 已通过 Cloudflare Pages 上线（mbabrand.com），是用户每天看的东西。demo 是实验性质（规则匹配覆盖面窄是已知风险），独立页把爆炸半径收敛到零——做坏了、想下线，都不影响主看板。
2. **迭代自由**：T2–T4 会在问答交互上反复试错（关键词表调优、组件样式打磨），独立页随便改；塞进 dashboard 里，每次动都要担心三区块回归。
3. **风格一致不靠同文件**：复用同一套资产即可——`:root` CSS 变量（`--paper #faf8f3` / `--accent #c1440e` / `--missing-bg #f0ede7` 等）、serif 字体栈（`ui-serif, "Noto Serif SC", "Songti SC", Georgia, serif`）、chart.js@4.4.4 同一 CDN、顶部 header 标识行。复制 30 行 CSS 变量，看起来就是一家人。
4. **同数据源、零后端**：`ask.html` 与 `dashboard.html` 同读 `data/deck.json`（相对路径，`fetch("data/deck.json")`），`file://` 也能打开，无需后端——和看板完全一样的部署姿势。
5. **互链只用纯加法**：`dashboard.html` 状态条旁加一行 `→ 问一问` 链接（1 个 `<a>` 标签，可单独评审，风险趋近于零）；`ask.html` 顶部放 `← 回指挥舱`。双向可达，但代码零耦合。
6. **二期再议合并**：如果 demo 转正（规则→LLM、二期多品牌），那时再评估把问答框嵌进 dashboard；一期保持"实验沙盒"定位，不提前合并。

页面结构（T4 实现时照此搭，不写代码先定骨架）：

```
ask.html
├── header（复用指挥舱标识行 + "← 回指挥舱"）
├── 问答框（input + 发送按钮，回车触发）
├── 8 个示例问题（一键试，§2.1 每意图取 1 个，横向 chips）
├── 结果区（按意图渲染受控组件 / fallback 纯文本 / 数据暂缺卡）
└── 页脚（一行小字：只读 demo · 数据来自 data/deck.json · 不调 LLM）
```

## 五、给 T2 / T3 / T4 的接口约定

- **T2（`scripts/ask_router.py`，trend #407）**：输入问题字符串 → 输出 `(intent_id | "unknown", matched_keywords[])`。`unknown` 触发 §三 fallback。纯标准库，不读 deck.json、不画图；同一问题每次返回同一意图（T5 验收确定性）。触发词表 = §2.3，裁决逻辑 = §2.2。
- **T3（图表组件，trend #408）**：实现 6 个渲染器，对应 §2.1 的 7 种输出形态（delta 条形图复用条形图渲染器，加正负着色）：指标卡 / 条形图（含 delta 变体）/ 雷达图 / 折线图 / 环形图 / 事件列表。复用 §四第 3 条的风格资产；null 降级按 §2.4。
- **T4（demo 页集成，trend #409）**：按 §四骨架实现 `ask.html`；问答框 + 结果区；8 个示例问题 chips（§2.1 每意图 1 个）；只读 `data/deck.json`，页面内无 POST、无 localStorage 写（T5 可审计）；fallback 逐字稿用 §3.2。

## 八、风险

- 规则匹配覆盖面窄、问法稍变就 miss → §2.2 三层裁决 + miss 了走诚实 fallback（不答比答错强）；二期再上 LLM 意图理解（PRD 非目标已明确）。
- deck.json 某段为 null → §2.4 "数据暂缺"卡，不画空图、不崩。
- 与 dashboard.html 的耦合 → §四独立 `ask.html`，已上线看板零风险。
- 范围蔓延（想加写操作/多品牌/开放式 HTML 生成）→ 本 PRD 红线：只读、单品牌、受控组件；comparison 多品牌对比是二期的事。
