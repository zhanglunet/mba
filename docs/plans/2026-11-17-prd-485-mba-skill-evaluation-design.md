# PRD-485/T1：mba 评委技能评估设计草稿

> 状态：设计草稿（T1），只设计不写代码；对应 trend issue：zhanglunet/trend#2345
> 来源：PRD-485《mba 评委技能评估》；本批统一主题：技能要验收
> 借鉴：NVIDIA/SkillEvaluator（Apache-2.0）、Claude-BugHunter（MIT）、stitch-skills（Apache-2.0）——只借鉴思路，不复用代码

## 目标

给 mba 的评委 panel skill 包配一套评估：定期回答“这些评委技能还管用吗”。评估结果落账，过期/重叠/失效的评委技能进整改清单，不直接删。评审复核收件箱只审评估过关的评委技能打出的分。

## 一、质量门：阈值与判定口径（草稿，阈值由设计评审定，实测后复核）

质量门回答一个问题：评委技能是否真让 agent 少打错分。

- 判定口径（草稿）：
  - 打错分率 = 与金标准评分（人工复核或历史定稿分数）偏差超过一个档位的评审数 ÷ 有技能参与的评审总数。
  - 行为改变率 = 有技能 vs 无技能（ablation 对照）时评分决策发生变化且变对的任务占比；只变不变好不算过关。
  - 触发率与采纳率：技能被触发的任务占比、触发后 agent 实际采纳建议的占比；触发率过低或采纳率过低都记为失效信号。
- 阈值（草稿，待评审）：
  - 打错分率 ≤ 10% 且不高于无技能对照组的 1/2；
  - 行为改变率 ≥ 10%；
  - 采纳率 ≥ 80%，低于 50% 直接判失效进整改清单。
- 判定规则：三项中任一硬指标不达标即“未过关”，进整改清单；全部达标为“过关”；数据不足（样本 < 30 个评审）判“待补测”，不判过关也不判失效。
- 过期判定：技能引用的评审标准/品牌口径已变更而技能未同步更新，即判过期，进整改清单。

## 二、重叠检测方法

- 方法：技能两两比对——① 文本/语义相似度（触发条件、评分维度、约束的 embedding 相似度，草稿阈值 ≥ 0.8 记候选重叠）；② 触发重叠率（同一评审同时触发两个评委技能的占比）；③ 产出重叠率（两个评委技能对同一维度的打分一致率，维度重复即重叠信号）。
- 判定：三项中有两项超阈值即判“重叠候选”，人工复核后确认；确认重叠的进整改清单（合并或拆分由整改定，不直接删）。
- 重点对：评委之间别重复打分维度——两个评委技能评同一维度、分不出彼此，即重叠；另查评委 skill 与其他技能的重复。

## 三、合成评测集：题源与证据要求

- 题源：造评审题考技能——题必须源自真实评审案例（Claude-BugHunter 式证据来源）：历史真实评审记录、真实打错分案例、真实争议复核案例；无来源的题不进评测集。
- 每道题必须带：题面（被评材料）、期望评分（金标准分数及理由）、证据链接（真实评审案例出处）、适用技能（考的是哪个评委技能）。
- 题型覆盖：正常评审、边界案例（易打错分）、争议案例（曾复核改分）三类；每类不少于 10 题，评测集总量不少于 30 题。
- 评测集版本化：每次新增/修改题目记版本号与变更原因；题目失效（对应评审标准已变更）即标记过期，不静默删除。

## 四、实测方案与行为变化度量

- 实测跑真实评审任务：在影子模式下跑真实评审任务（分数只记评估报告，不进品牌审计报告、不落账为正式分数），对照组为无技能的 agent。
- 度量：打错分率、行为改变率、采纳率（同质量门口径），另记维度区分度（评委技能之间打分的相关性，越高越疑似重叠）；行为变化只认“变对”的部分，变错了记负分。
- 样本量：每轮实测不少于 100 个真实评审任务；结果与合成评测集结果交叉核对，不一致时以实测为准并记入报告。
- 频率：每轮评估出报告；技能包有变更（新增/修改技能）时加跑一轮。

## 五、评估结果落账与整改清单

- 每次评估产出评估报告落账：报告含每个技能的四项得分、过关/未过关/待补测结论、重叠候选清单、实测与评测集对照结果；报告 append-only，只增不改。
- 整改清单 append-only：过期/重叠/失效的技能进清单，记原因、证据、建议动作（修/合并/拆分）；评估结论绝不直接作为删除依据，技能下线另走审批。
- 闸门（T3 做）：评估未过关的评委技能不得进入下游——其打出的分不进评审复核收件箱。

## 六、与已有 PRD 的边界

- PRD-426（评审流水线审报告）：审产物（报告），本条评技能本身，不审产物。
- PRD-380（评审结论验证台）：验发现真假，本条验技能管不管用。
- PRD-366（收件箱）：管等人拍板，本条不管拍板流程。
- PRD-449（监督台）：人审 agent 干活的过程，本条不审过程、只量技能产出。
- PRD-022（评委 panel 独立验收测试）：给单个评委写测试；本条评整个评委包的健康度，不评单个评委。
- PRD-465（skill 发现层）：管有什么技能；本条管技能管不管用。
- 独立验收测试（PRD-012/022/034/037）：给单个 skill 写三层测试；本条评整个包的健康度。
- 不改技能包本身的形态与上架流程。

## 七、红线

- 只借鉴思路，不复用代码（SkillEvaluator / Claude-BugHunter / stitch-skills 均为思路借鉴）。
- 评估只进整改清单，绝不直接删技能；技能下线另走审批。
- 实测分数不进正式审计报告：影子模式的分数只用于评估，绝不落账为正式分数。

## 八、T2 交接要点

T2 按本设计实现最小版：质量门 + 重叠检测在真实技能包上跑通，产出首份评估报告落账。阈值以设计评审定稿为准，实测后复核调整。
