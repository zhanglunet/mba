# 26 — MBA 系统如何运作(System Overview)

> **面向**:第一次接触 MBA 的人(读者 / 贡献者 / AI agent),想在十分钟内搞清楚"这台机器整体是怎么转的"。
> **不重复**:单次审计内部的打分细节见 [`04-pipeline.md`](04-pipeline.md) 与站上的
> [How it works](https://mbabrand.com/how-it-works);代码分层见 [`03-architecture.md`](03-architecture.md)。
> 本文讲的是**它们如何串成一个持续运转的系统**。
> 网页版:**[mbabrand.com/system](https://mbabrand.com/system.html)**(含流程图)。

---

## 1. 一句话

MBA 把"品牌影响力"这件本来靠感觉的事,拆成**可打分、可比较、可复盘**的东西:
让 43 位从一手语料蒸馏出来的**人物评委**,按 **7 维度 × 5 镜头**对品牌各自独立打分,
Lead 合成一份**带版本号**的报告;此后由**每日舆情监控**持续喂料,信号累积到阈值就重审,
于是同一品牌随时间的每一次变化都留痕、可对比。

## 2. 全景:两个输入、一个核心、三个出口

```
   输入                        核心                          出口
┌────────────┐         ┌──────────────────┐         ┌──────────────┐
│ 人物语料    │────────▶│  编组:10 套 panel │         │ 网站(报告页) │
│ 43 位评委   │         │  按行业选评委      │────────▶│ JSON API×11  │
│ 一手著作/访谈│         │  利益冲突自动回避  │         │ MCP 工具×16  │
└────────────┘         └────────┬─────────┘         └──────────────┘
                                │                            ▲
┌────────────┐          ┌───────▼────────┐                   │
│ 舆情信号    │─────────▶│ 审计:7 维×5 镜 │───────────────────┘
│ 24 品牌     │  触发重审 │ N 位评委独立打分│   版本化报告 v1→v2→…
│ 每日累积    │          └────────────────┘
└────────────┘
```

**关键**:两个输入的**节奏完全不同** —— 人物语料是"慢变量"(深化一套评委要 6 路一手调研),
舆情信号是"快变量"(每天自动进 170~180 条候选)。系统的设计难点就在于**让快的那条不要污染慢的那条**:
舆情只能**触发**重审,永远不能自己改分。

## 3. 两个循环

### 循环 A — 审计循环(慢,人驱动)

```
/mba <品牌>  →  Phase 0 路由(FRESH / EVOLUTION)
              →  Phase 1 立 PRD,人确认
              →  Phase 2 N 个子代理并行取证
              →  Phase 3 Lead 合成证据包
              →  Phase 4 N 位评委 in-character 独立打分
              →  Phase 5 Lead 合并 → report.md + report.html + versions/ 快照
```

细节见 `04-pipeline.md`。这里只强调三点:

1. **评委互不可见** —— 打分阶段并行且隔离,异议是真异议,不是互相抄。
2. **利益回避是硬规则** —— 评委本人是该品牌创始人/董事时自动剔除(`--panel-drop`),
   已在 Microsoft / Huawei / Tesla / Palantir 四家真实触发。
3. **报告不可变** —— 每版落 `versions/v{n}_<date>.{md,html}` 快照,旧版永远可回溯。

### 循环 B — 舆情循环(快,机器驱动,每天)

```
02:17 UTC  watch-discover
   │  ① 发现:按品牌抓公开新闻源 → 候选(每日 170~180 条)
   │  ② LLM 预分类:判 维度/严重度/方向/镜头 + 置信度
   │  ③ 自动开「建议入库」PR → 折入 watch/<品牌>/events.yaml
   │  ④ 人审 diff 后合并          ← ★ 人工闸门
   ▼
watch/<品牌>/events.yaml(24 个品牌,每日累积)
   │
   │  ⑤ 触发规则(30 天滚动窗口,只算未消费事件):
   │       R1  P0 ≥ 1          R2  P1 ≥ 3
   │       R3  加权 4×P0 + 2×P1 + 0.5×P2 ≥ 6
   ▼
「建议重审」→ 首页亮灯 + L1 预筛(见 §4)
```

**两条循环的交汇点**:触发之后,由**人**发起 EVOLUTION 重审,评委以 vN 为基线重新打分,
被消费的事件标记 `consumed_by: vN`(于是不会重复计价),报告出 vN+1。

## 4. L1 预筛:一道更便宜的闸门(2026-07 新增)

完整重审(下称 L2)一个品牌要读全篇报告加全部未消费事件,**约 25k token 输入**;
而 15 家实测下来**最大只动 0.16 分**,绝大多数结论是"没变化"。
于是加一道便宜的前置闸门:**只看标题**判断"这家有没有真正落地的硬事实"——
筛完全部 17 家触发品牌的成本,才约等于 L2 重审一家。

设计要点(六次真跑迭代出来的,详见 `16-brand-watch-implementation.md` §9.5):

| 要点 | 为什么 |
|---|---|
| **逐事件**打类别标签,不给品牌级结论 | per-brand 会让模型"挑最弱的一条说不" |
| 类别取自 **9 类封闭白名单**,挑不出即 D | 开放判断在弱模型上不稳,分类才稳 |
| 白名单**由代码校验**,自创类别一律作废 | 不靠模型自觉 |
| 品牌结论由**程序汇总**(任一命中即值得重审) | 结构上杜绝挑一条说事 |
| 每条判断**引用事件 id**,覆盖率如实报出 | 可逐条复核;静默漏答比误判更危险 |

**边界**:L1 只回答"值不值得请评委重新打分",**永远不判断分数涨跌**。
目前**只能手动触发、默认不写库**——判断质量充分验证前不进每日流程。

## 5. 谁在把关:六道门禁 + 一条铁律

**铁律:审计分数从不自动变。** 只在评委 in-character 重打时变,且**合并 PR = 人工闸门**。
AI 做的是分类与搬运,不是打分。

CI 上跑的硬 gate(本地同一套命令即 CI 镜像,见 `CLAUDE.md`):

| 门禁 | 守什么 |
|---|---|
| `firewall_check.py` | **反捏造**:SKILL 里带署名的逐字引用,必须在本套 research 语料里规范化后逐字存在 |
| `check_structure.py` / `quality_check.py` | 43 套评委 SKILL 的结构与质量(全量 6/6) |
| `check_self_conflict.py` | 每套 SKILL 声明自身 `--panel-drop`,利益回避不靠自觉 |
| `validate_watch.py` | 舆情 schema + 适用性矩阵对齐发布白名单;判断字段恒标 `model-judged` |
| `check_consistency.py` | 17 格一致性:版本对齐、docs 索引、评委数、工具数、维度口径、产业、首页卡片…… |
| `validate_report.py` / `check_report_integrity.py` | 报告分数自洽(矩阵列和 == 声明总分)、HTML 与 md 不漂移 |

反捏造的具体纪律(引号内必须是源站原话、中文按去空格匹配、provenance 如实标注)见 `CLAUDE.md` 坑 #3。

## 6. 三种用法

| 方式 | 要不要 key | 能做什么 | 适合谁 |
|---|---|---|---|
| **HTTP JSON API**(11 端点) | 不要 | 读已发布的 24 家报告 / 评委 / panel / 搜索 | 任何人、任何 agent,`curl` 即可 |
| **MCP server**(16 工具) | 要 | 把 panel 与评委接进自己的 AI 助手 | Claude Desktop / IDE 用户 |
| **Claude Code skill**(`/mba`) | 要 | 真跑完整流水线,产出新报告 | 想审新品牌的人 |

详见站上 [API / CLI 指南](https://mbabrand.com/agents) 与 `README.md` §5.2;
agent 自我发现入口是 `/llms.txt`。
